# Разработка Pingvi

## Требования

- Apple Silicon, macOS 14+.
- Xcode с macOS SDK и Swift toolchain, поддерживающим проект. Локальная проверка выполнялась с Xcode 26.
- Python 3.12+ для скриптов сборки и безопасной распаковки runtime.
- Интернет при первом скачивании закреплённого runtime.

Для запуска готового приложения внешний Python не нужен. Агентам и herdr нужны собственная установка и авторизация.

## Сборка

```sh
bash tools/build.sh
bash tools/package-dmg.sh --local
```

Первый скрипт создаёт `dist/Pingvi.app`, второй — тестовый DMG с суффиксом `-local` и SHA-256 рядом. Бинарники и кэш сборки не входят в Git. Распространяемый DMG собирается через `bash tools/package-dmg.sh --release` (это режим по умолчанию), после настройки Developer ID и notarization.

`tools/python-runtime.lock.json` фиксирует Python standalone, архитектуру, URL и SHA-256. Неверная контрольная сумма останавливает сборку. Тексты лицензий входят в приложение. Обновление runtime требует проверки контрольной суммы, переносимости, лицензий и тестов.

## Проверки

```sh
swift test
python3 -m unittest discover -s Tests
python3 tools/check-bundled-runtime.py
```

Последняя проверка требует собранного `.app`. Она копирует его в папку с пробелами, использует отдельный профиль, проверяет встроенный Python, установку/исполнение/отключение hook, замену приложения и сохранение черновиков. Рабочие настройки пользователя не изменяются.

```sh
python3 tools/check_chat_transport.py
```

Этот тест требует работающего herdr. Он создаёт отдельный workspace с процессом-приёмником и проверяет аргументы, многострочную вставку и Enter. Платная модель не запускается; тестовый workspace закрывается.

## Иллюстрации README

```sh
dist/Pingvi.app/Contents/MacOS/AgentAttention --preview-dashboard docs/media/dashboard-2026-09.png
dist/Pingvi.app/Contents/MacOS/AgentAttention --preview-floating docs/media/floating-question-2026-09.png
```

Для тёмного варианта добавьте `--preview-dark` к `--preview-dashboard` или `--preview-floating`.
Для просмотра найденного сообщения в демонстрационной переписке добавьте `--preview-search` к `--preview-dashboard`.
Для заметки, шаблонов или обзора результатов используйте соответственно `--preview-note`, `--preview-templates` или `--preview-results` вместе с `--preview-dashboard`; эти режимы используют вымышленные данные.
Для окна настроек добавьте `--preview-settings` к `--preview-dashboard`.

Экспортирует настоящий интерфейс с вымышленными проектами без опроса пользовательских сессий. Не используйте рабочие диалоги в публичных скриншотах.

`--preview-floating` показывает настоящий компонент плавающей карточки на нарисованном демонстрационном фоне редактора. Рабочий стол и окна пользователя не захватываются. После изменения кода сначала пересоберите приложение; для быстрого экспорта также можно использовать `swift run AgentAttention --preview-floating docs/media/floating-question-2026-09.png`.

## Подпись и распространение

`tools/build.sh` допускает ad-hoc подпись для разработки. Для распространяемого DMG задайте `SIGNING_IDENTITY` (имя или SHA-1 доступного сертификата Developer ID Application) и `NOTARY_PROFILE` — имя заранее настроенного профиля notarytool в Keychain. Секреты в файлы проекта не записываются. Без этих параметров `package-dmg.sh --release` останавливается до сборки; для локального теста нужен явный `--local`.

Скрипт подписывает вложенные Mach-O и приложение, отправляет ZIP приложения на notarization и прикрепляет ticket к приложению до упаковки. Затем подписывает и нотарифицирует DMG, прикрепляет его ticket и проверяет Gatekeeper для приложения и образа. Эта ветка требует проверки с реальным сертификатом; опубликованная beta 9 остаётся ad-hoc и не становится нотарифицированной от изменения скрипта.

Разрешение уведомлений и успешный `UNUserNotificationCenter.add` не доказывают показ баннера. Автотесты `NotificationDeliveryTests` проверяют ожидание решения по разрешению, запрет, стиль без баннеров и ошибки API. Видимость баннера проверяется вручную на целевой macOS. `PINGVI_APP=/Applications/Pingvi.app bash tools/notification-check.sh` использует кнопку теста в интерфейсе, в том числе если приложение уже запущено.

Для согласованной предварительной публикации без Developer ID есть явный режим `bash tools/package-dmg.sh --adhoc`. Он принудительно использует ad-hoc подпись, создаёт образ с суффиксом `-adhoc` и не выполняет notarization. В описании такого релиза обязательно указываются ограничения Gatekeeper и инструкция ручного открытия.

## Перед релизом

- Скачанный DMG: копирование в Applications, извлечение образа, запуск.
- Чистый профиль: отсутствие CLI, отказ и повторная выдача разрешений macOS.
- Для каждого заявленного источника: вопрос, ответ, подтверждение продолжения, отказ и отмена.
- Изменение вопроса до отправки, двойное нажатие, разрыв связи, восстановление приложения.
- Несколько окон и панелей: точная адресация ответа и честная индикация ограничений перехода.
- Обновление приложения и hooks с сохранением пользовательских данных.
- Светлая/тёмная тема, клавиатура, VoiceOver и доступность на заявленных версиях macOS.

Модульные тесты и экспорт интерфейса не заменяют эти проверки на другом Mac.
